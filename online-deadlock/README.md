# Веб-версия Bobrs Battle Part 2

Откройте [игру](https://bobrikindeadlock.github.io/Bobrs-Battle-Part-2/). Пройдите оба этапа в одной вкладке. Для сетевой игры откройте ворота, создайте комнату до призыва колоды и отправьте приглашение Артемону. Каждый капитан открывает ворота на своём устройстве. После первого драфта и ролика ведущий открывает Deadlock в той же комнате.

Сетевые действия и номер хода проверяет ведущий. В первом драфте два браузера проигрывают подтверждённое действие с одним и тем же источником случайности. Завершённое состояние ведёт вкладка Макарыча. Будьте готовы оставить её открытой. Артемон может вернуться по приглашению из прежнего браузера. Локальные сценические эффекты не меняют составы или порядок ходов.

Сборка для Pages использует исходные сцены и ресурсы. Для видео нужно загрузить Git LFS:

```sh
git lfs pull
python3 online-deadlock/build.py _site
node --test online-deadlock/rules.test.mjs
```

Готовая игра в `_site/index.html`. Дополнения для сетевых состояний применяются к контроллерам при сборке. Существующий ZIP работает по-прежнему. Ранее опубликованные ссылки и передача результатов из ZIP открывают совместимый вход второго этапа по `deadlock.html`.

PeerJS 1.5.5 поставляется вместе с лицензией MIT. Ведущий и гость задают идентификаторы локально, поэтому WebSocket открывается без запроса `/peerjs/id`. Комната использует публичную сигнализацию PeerJS, а игровые данные передаются между браузерами через WebRTC. При обрыве WebSocket игра делает до двух автоматических повторов. Явный отказ сервера останавливает попытки и выводит сообщение.

В Deadlock попадают два состава из подтверждённого снимка первого драфта. При повторном входе гость получает эти же составы и текущие пики и баны.
